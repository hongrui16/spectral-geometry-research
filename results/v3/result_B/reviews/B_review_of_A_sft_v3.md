所以实际施加的步长范数 = `s_rel × ‖dense AdamW 步长‖`,而 dense 步长范数本身随 lr 走。
两个旋钮乘在同一个量上。实测(B 亲手复算,`metrics.csv` 里 27 个受跟踪矩阵的 ΣH_G_fro 中位数):

| 配置 | median Σ‖H‖_F |

**比值 1.05。这两格是同一个工作点**,它们一致只是自洽性检查,不是跨条件复现。

因此:

- **草稿 251 行"r 维干预在 lr×s_rel 跨 100 倍的范围内都停在同一点"不成立。**
  全部 8 个 r 维格子的实际步长范数张成 0.01880 → 0.10620 = **5.65 倍**,不是 100 倍。
- **草稿 253 行"r 维更新对 lr 和 s_rel 都不响应"不成立。** 两者是一个旋钮;
  而且它确实响应:训练 loss 末 50 步随 s_rel 单调走
  0.5860 → 0.5405 → 0.5069(spectrum),seed 间离散只有 0.0004。
  不响应的只是两个 eval 指标,且在其噪声之内。
- 采样只覆盖了单侧:全部 10 个 r 维 run 的 `intervention_scale ∈ {1,3,10}`、
  `lr ∈ {1e-6, 1e-5}`,**没有任何 s_rel<1 或 lr<lr\* 的格子**。

**裁决本身不受影响**:预注册规则(`unified_paper_document_v3.md:175`)要求
"r 维前沿**严格在** dense 前沿右上方",r 维点并非严格右上,所以规则确实返回阴性。
但规则返回的是"**不占优**",不是"不响应"、也不是"前沿重合"。建议把 252/253 行改写为
**欠功效 / 不占优**,并把 100 倍改成实测的 5.6 倍。

## 确证发现 2:草稿 222 行的转录错误

草稿:`| spectrum_matched | r | 0.386/0.392(0.389) | 0.475/0.473(0.474) |`
原始:seed0 = 0.392 / **0.472**,seed1 = 0.386 / **0.476**。
GSM8K 两个 seed 顺序写反;MMLU 两个数**在任何一个 run 里都不存在**。
均值(0.389 / 0.474)是对的,其余格子全部对得上。

## 观察(B 亲手复算,但**未**经对抗验证):r 维 MMLU 与 mn 维零重叠

lr\* 上全部 10 个 run 的终值 MMLU:

```
r  维: 0.472 0.474 0.476 0.476      (spectrum ×2, random_ext ×2)
mn 维: 0.449 0.450 0.450 0.453 0.457 0.462   (full, frame_matched, exact_iso 各 ×2)
```

**零重叠**;合并差 **+0.0210**;置换检验(4 vs 6,单侧)**p = 1/210 = 0.0048** ——
观察到的这个划分是 210 种里最极端的一种。按 H-1(两字典不可分)与 H-2(三个 mn 臂不可分)
——**这两条你已经判 ✅**——合并本身是被许可的。

同时 r 维的 GSM8K 更低(0.389 / 0.375 对 0.415 / 0.400 / 0.403),所以这是**权衡**而非占优,
预注册的严格占优规则返回阴性是对的。但"前沿**重合**"这个说法与上面的零重叠不符:
r 维点落在权衡曲线上一个**可测量地更高 MMLU** 的位置。建议措辞从"重合"改为
"不占优(GSM8K 更低、MMLU 更高)"。要把 C5 SFT 钉成终判,建议至少在 s_rel∈{3,10} 上各补 2 个 seed
(现在是 n=1),并补一格 s_rel<1。
