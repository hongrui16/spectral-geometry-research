# 前一版本(v3)的状况(一段话)

- **v3 主线**:权重奇异基不是后训练的特权坐标系(C1 测量、C2 谱字典 ≈ 随机字典、C3 投影更新的功能步长小两个量级);第二层是 C4(保谱/去谱在健康区与 dense 不可分)与 C5(r 维约束是否改善折中),二者都以"先找到健康 lr\*"为闸门。
- **成立**:C1、C2、C3 在 SFT 与 RLVR 两侧都成立;C4 在两侧成立(以 frame_matched 论证);H-0 两侧找到健康 lr\*(SFT 1e-6、RLVR 2e-7,均为 lr×1 的 1/10,E-v3-0c 的预测命中)。
- **推翻**:C5(r 维约束改善折中)两侧阴性,且 RLVR 上 r 维被 dense 严格占优;v2 遗留的"mn 维崩 MMLU"是 lr×1 崩溃区加格式假象。
- **作废**:exact_iso 臂的全部 v2/v3 结果(引擎数值缺陷:CUDA 默认 SVD 求解器 fp32 误差 1e-4,逐步钉谱注入 4 倍 dense 步的噪声;09-17 已修,重跑中)。
- **主线是否还成立:成立,且比 v3 预期更干净。** 但它是一组否定式结论,覆盖面只有一个 0.8B 模型、一个任务、300 步。v4 不换主线,补覆盖面并加一个正面主张。

# 1. v3 实验总结(数字来自登记处;GSM8K n=500,MMLU n=1000;base 0.546 / 0.483)

## 1.1 闸门(H-0):健康 lr\* 是 lr×1 的 1/10,两侧一致

| 范式 | lr×1/30 | lr×1/10 = lr\* | lr×1/3 | 判据 |
|---|---|---|---|---|
| SFT(A,2 seed) | 0.390 / 0.461 健康 | **0.415 / 0.456** 健康(MMLU 余量 +0.003) | 0.420 / 0.302 MMLU 崩 | reward/loss 不回落、MMLU ≥ base−0.03、seed 差 ≤0.04 |
| RLVR(A+B 合并) | 0.562 / 0.479 健康(B,2 seed;A 2 seed 在跑) | **0.646 / 0.471** 健康(6 run) | 0.699 / 0.457 离散 0.05–0.07 且 MMLU 压线 → FAIL(4 run) | 同上 |

E-v3-0c 在闸门之前用 8 步捕获预测 lr\* ≈ lr×1/10,两侧命中。这是 v4 正面主张的种子(§4)。

## 1.2 主结果(lr\*,GSM8K / MMLU,A+B 按独立样本合并)

| 更新 | 维度 | SFT(2–3 seed) | RLVR(4–6 run) | RLVR reward 末 100 步 |
|---|---|---|---|---|
| full(dense) | mn | 0.415 / 0.456 | 0.646 / 0.471 | 0.56 |
| frame_matched(等范数保谱) | mn | 0.400 / 0.454 | 0.634 / 0.473 | 0.54 |
| exact_iso(去谱)| mn | 作废,重跑中 | 作废,重跑中 | – |
| spectrum_matched(谱字典) | r | 0.389 / 0.474 | 0.556 / 0.478 | 0.34 |
| random_ext(随机字典) | r | 0.375 / 0.475 | 0.556 / 0.477 | 0.34 |

逐项判定(预注册规则:margin GSM8K 0.03 / MMLU 0.02,|t| ≥ 2 才算可分):

- **H-1 谱字典 ≈ 随机字典(C2)**:SFT +0.014 / −0.001(3 seed 亦成立);RLVR 0.000 / +0.001(lr×1 上 −0.026)。**成立,两侧。** B 提醒:RLVR 的 lr\* 上两臂都停在 base 附近,有效检验在 lr×1。
- **H-2 保谱 ≈ dense(C4)**:SFT +0.015 / +0.003;RLVR +0.012 / −0.003(11 run)。**成立,两侧。** 趋势上 RLVR 的保谱略慢(reward 0.54 vs 0.56,单步 KL/‖H‖² 低 20–36%),未过判据。
- **H-3 / C5 r 维约束改善折中**:SFT 上 r 维是"GSM8K 低 0.03、MMLU 高 0.02"的另一个权衡点,无一方占优;RLVR 上 r 维 GSM8K 低 0.09(t ≈ −11),MMLU 相同,**dense 严格占优**。s_rel 与 lr 扫描:SFT 的 r 维任务指标不响应步长(loss 响应),RLVR 的 r 维响应但到 lr×1 仍在 dense 之下,落在 dense 的 lr 前沿上。**阴性,两侧,终判。**

## 1.3 零训练与单步诊断

- **E-v3-0c 单步功能步长**:等范数 r 维投影更新的单步 KL 比 dense 小 2–4 个数量级(SFT 300 倍,RLVR 3000 倍);frame_matched 与 dense 同量级。这是 C3,也是 C5 阴性的机理解释。
- **E-v3-0a 累计 KL(39 个 v3 终点 ckpt)**:RLVR 下 r 维累计 KL 只有 dense 的 1%(lr\*),s_rel 10 或 lr×1 也只到 5–25%;SFT 下达 60%。SFT 累计 KL 对 lr 几乎不敏感(lr×1/30 到 ×1/3 都是 0.85–0.87)而权重位移差 5 倍。
- **E-v3-0b MMLU 格式检查**:健康区所有 run 无格式假象(字母作答比例 0.84–1.0 vs base 0.865);v2 lr×1 dense 的 MMLU 0.24 是格式假象;SFT lr×1/3 的 0.30 同时是格式漂移与真实损失。
- **exact_iso 缺陷**:两边独立确认(A:186 矩阵中位谱漂移 11 倍 dense;B:fp64 重算 33 倍)。根因是 CUDA 默认 gesvdj 求解器 fp32 误差 1.5e-4;gesvda 为 2.5e-8 且更快。修复后加等范数匹配,5 个臂重跑中。

## 1.4 方法论发现(进论文的 protocol 一节)

1. 等范数 ≠ 等推进量:等 Frobenius 范数的投影更新与 dense 的 cos 只有 0.02,功能步长小两个量级。任何"等范数干预"比较都必须报告单步 KL。
2. dense 在 lr×1 是崩溃态,以它为锚的所有比较不可靠;必须先扫 lr 找健康区。
3. MMLU 单点评测需要格式检查,否则大 lr 的"能力崩溃"可能是字母作答比例崩溃。
4. 逐步 SVD 干预必须核对求解器精度;fp32 GPU SVD 的默认求解器不够。
5. 同 seed 跨硬件不复现(MIG vs A100,GSM8K 差中位 0.010、最大 0.044),多硬件结果按独立样本合并。
6. 阈值判定 5 次落在 0.002 以内;引用 HEALTHY/FAIL 必须带余量;2–3 seed 下 |t| ≥ 2 从不起作用,规则实际退化为点估计加 margin。

# 2. 差距分析:离顶会主会投稿水平还差什么

审稿人视角下现有工作的定位:一组可靠的否定式结论加一套诚实的 protocol,在单模型单任务上。会被追问的四点,按致命程度排序:

| # | 缺口 | 审稿人会怎么说 | v4 对应 |
|---|---|---|---|
| G1 | **没有正面主张** | "所以我该怎么做?" 全文是"X 不重要、Y 不占优"。 | §4 P-1:单步功能步长诊断预测 lr\* 与干预是否有效;P-2:实践处方 |
| G2 | **覆盖面**:一个 0.8B、一个任务、300 步 | "SVD 基不特殊"这种普遍性主张在一个点上不能成立。 | §5 新增一个模型规模(2B)与一个非 GSM8K 任务;两者都过同一套闸门与裁决 |
| G3 | **与已有工作没有正面对话** | LoRA/低秩适配、正交化更新(Muon 类)、谱正则/谱约束训练;我们的 r 维臂与 LoRA 的关系、exact_iso 与正交化更新的关系。 | §5 E-v4-3 LoRA 基线在同一前沿上;§1 相关工作段改写 |
| G4 | **C4 的去谱一半缺席** | "保谱 ≈ dense"只是一半;"禁止谱变化也 ≈ dense"才是题目问的事。 | exact_iso 修复后重跑(已提交),两侧各 2–3 seed |

次要缺口(写作解决):seed 数少时的统计表述;300 步的外推边界;只报终点还要报轨迹。

**判断**:G1 与 G4 是必须的;G2 至少补一个维度(模型或任务),两个都补才稳;G3 只需一个 LoRA 基线。做完 G1–G4 的最小集合,论文从"分析型短文"变成"有处方、有跨模型跨任务证据的实证论文"。

# 3. 主张,按可靠性分层(v4)

**已可靠(v3 两侧成立,不再检验,只扩覆盖)**
- C1 观测梯度几何由噪声主导,谱 ordering 不是学习信号。
- C2 权重奇异基 ≈ 同维随机基:把更新限制在谱方向与限制在随机方向,结果不可分。
- C3 等范数投影更新的功能步长比 dense 小两个量级。
- C4 等范数保谱更新 ≈ dense(去谱一半待 exact_iso 重跑)。
- C5 阴性:r 维约束不改善任务/能力折中,只是学得慢;dense 在健康 lr 上不被任何 r 维干预占优。

**v4 待检验(新增)**
- **P-1 功能步长诊断**:8 步捕获测得的单步 KL/‖H‖²(dense)与投影更新的 KL 比,在训练之前预测 (a) 健康 lr\* 的档位,(b) 哪些干预会"几乎不训练"。v3 已在 0.8B/GSM8K 两侧命中一次;v4 在每个新单元里**先做预测、后跑闸门**,预注册。
- **P-2 实践处方**:在健康 lr 下,dense ≥ 任何等范数子空间约束;想要"保能力"应调 lr 而不是限制子空间。这是 C5 阴性的正面表述,v4 用 LoRA 基线把它和实践连起来。
- **G 泛化**:C2、C4、C5 在第二个模型规模与第二个任务上重复。

**明确不作的推断**:不推断到 >2B 模型、>300 步、非可验证奖励的 RL;不声称 exact_iso 修复后的任何方向性结果(先看数据)。

# 4. 假设表与预先锁定的裁决规则(v4)

margin 与 v3 相同(GSM8K 0.03、MMLU 0.02);每臂 ≥ 3 个独立 run(不同 seed 或不同硬件);报告点估计、经验 SE 与 margin 余量。

| 假设 | 检验 | 成立 | 不成立 |
|---|---|---|---|
| H4-0 闸门 | 每个新单元(模型×任务×范式)扫 lr {×1/30, ×1/10, ×1/3},判据同 v3 | 存在健康 lr\* | 该单元换配方(加 KL 惩罚或加大 batch),不进主结果 |
| **H4-P1 诊断预测** | 闸门之前,用 8 步捕获的 KL/‖H‖² 预测 lr\* 档位与"r 维臂几乎不训练";预测写进登记处再跑 | 4 个单元中 ≥ 3 个命中 lr\* 档位,r 维"不训练"预测全部命中 | 诊断降为描述性指标,P-1 从主张中删除 |
| H4-1 泛化 C2 | 每单元 lr\* 上 spectrum_matched vs random_ext,3 run | 差在 margin 内 | 在哪个单元不成立就在哪个单元写明,C2 加限定 |
| H4-2 泛化 C4 | 每单元 lr\* 上 full vs frame_matched vs exact_iso(修复版),3 run | 三者两两在 margin 内 | 若 exact_iso 或 frame 与 dense 可分,C4 改为"范式/规模依赖",方向写明 |
| H4-3 泛化 C5 | 每单元 r 维臂对 dense 的前沿位置 | r 维不在 dense 前沿右上方 | 若在某单元占优,C5 改判并成为正面结果 |
| H4-L LoRA 基线 | 0.8B/GSM8K 两范式,LoRA(秩 = r 维臂的 r)扫 lr 3 档,2 seed,画在同一前沿 | LoRA 落在 dense 前沿上或其下 | LoRA 占优 → P-2 处方要加"低秩参数化 ≠ 等范数子空间约束"的限定 |

# 5. 实验设计(v4)

## 5.0 单元与代码

- 单元 U0:Qwen3.5-0.8B × GSM8K(v3 已完成;只补 exact_iso 修复版与 LoRA 基线)。
- 单元 U1:**Qwen3.5-2B × GSM8K × RLVR**(本地已有 2B 权重;fp32 + AdamW 约 32 GB,需 A100.80gb,MIG 不够)。
- 单元 U2:**Qwen3.5-0.8B × 第二任务 × {SFT, RLVR}**。任务要求:可验证奖励、有独立能力保持基准、非 GSM8K 分布。首选 MATH(Hendrycks,train 按难度 1–3 取子集,eval MATH-500,能力保持仍用 MMLU);需下载数据集到 HF 缓存(离线模式)。
- 单元 U3(可选,视 U1/U2 进度):Llama-3.2-3B-Instruct × GSM8K × RLVR,换模型家族。
- 代码 `*_v4/`:从 v3 复制,叠加 (a) 已修复的 exact_iso,(b) `--model` 与 `--task` 参数化(数据加载、reward、eval 脚本按任务分派),(c) LoRA 模式(`--lora-rank r`,PEFT 或手写,fp32),(d) `analysis_v4/predict_lr.py`:从 8 步捕获输出 lr\* 预测与"不训练"预测并写入登记处。

## 5.1 批次(每批一天;批次之间有闸门)

**批次 0(第 1 天,U0 收尾)**:exact_iso 修复版 RLVR 3 seed + SFT 2 seed(已提交);LoRA 基线 2 范式 × 3 lr × 2 seed = 12 run(MIG)。同日 A 完成 `predict_lr.py`,用 U0 的 8 步捕获回测(必须复现 v3 的 lr×1/10 预测)。

**批次 1(第 2 天,新单元的诊断与闸门)**:U1、U2 各做 8 步捕获(dense、spectrum、random、frame、exact_iso 五路,seed 0)→ `predict_lr.py` 输出预测并登记 → 再跑 dense lr 扫描 3 档 × 2 seed(U1 RLVR 6 run,A100;U2 SFT+RLVR 12 run,MIG)。

**批次 2(第 3–4 天,新单元主结果,在各自 lr\* 上)**:每单元每范式 frame_matched / exact_iso / spectrum_matched / random_ext × 3 run。U1:12 run(A100,约 8 h/run);U2:24 run(MIG,SFT 2 h、RLVR 5 h)。

**批次 3(第 5 天,补 seed 与前沿)**:dense lr\* 第 3 seed;r 维 s_rel 10 或 lr×1 各 1 run(看是否沿前沿移动);按批次 2 的裁决决定是否需要 U3。

## 5.2 预算(GPU 小时,按 v3 实测)

| 批次 | run 数 | 估计 | 硬件 |
|---|---|---|---|
| 0 | 5 + 12 | 17 × 3.5 h ≈ 60 h | MIG |
| 1 | 10 捕获 + 18 闸门 | 10 × 0.3 h + 6 × 8 h + 12 × 3.5 h ≈ 93 h | A100 + MIG |

| 3 | ≈ 10 | ≈ 50 h | 混合 |
| 合计 | ≈ 80 run | ≈ 380 GPU 小时 | A、B 各承担一半,约 5 天 wall |

## 5.3 停止条件

- 批次 1 若 U1 或 U2 找不到健康 lr\*:该单元换配方一次(加 `--kl-beta 0.01` 或 batch ×2);再失败则该单元只保留诊断结果,不进主表。
- 批次 2 若某单元 C2 或 C4 不成立:不追加实验,如实写为"规模/任务依赖",这本身是结果。
- H4-P1 若预测 4 个单元中命中 < 3:P-1 降为描述性指标,论文回到 protocol + 泛化的叙事,仍可成文。
